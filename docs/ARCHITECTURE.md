Состояние изучено 29 сентября 2026 года по рабочей папке, включая незакоммиченные файлы. Основное правило — `../AGENTS.md`.

## Оформление и поведение

| Файл | Ответственность и особенности |
| --- | --- |
| `css/style.css` | Базовые стили, сетки, общие элементы и адаптивность |
| `css/theme.css` | Текущее оформление поверх базы, токены, логотип, адаптивные уточнения. Импортирует `catalog.css` и `features.css`; часть правил каталога продублирована ниже импортов, поэтому важен каскад |
| `css/catalog.css` | Слайдер, карточки объектов, каталог и лаконичные внутренние страницы |
| `css/features.css` | Фото методов, иконки преимуществ и этапов главной |
| `css/pest-game.css` | Мини-игра, динамически подключается из `interactions.js` |
| `css/service-page.css` | Старый вариант оформления услуг; текущие публичные страницы его не подключают |
| `js/main.js` | `CONFIG`, базовые словари `i18n`. В словарях остались исторические ключи; их наличие не означает, что старые секции надо вернуть |
| `js/interactions.js` | Актуальные переопределения переводов, язык, слайдер, меню/модальные окна, FAQ, формы, телефон, WhatsApp, локальная копия заявки, год, прокрутка наверх; загрузка игры |
| `js/pest-game.js` | Изолированная игра: диалог, 15 целей, счёт, повторный раунд, RU/KZ, движение и управление с клавиатуры |
| `images/` | Используемые и исторические изображения. Не удалять «неиспользуемое» попутно. Происхождение генераций: `images/GENERATION.md` и файлы `prompts.json` |

Перевод применяется через `data-i18n` и `innerHTML`. Русские тексты слайдов берутся из текущего HTML; другие актуальные тексты могут переопределяться в `interactions.js`. При правке проверять итог после выполнения JS и после RU → KZ → RU, а не только исходную разметку.

## Общий каркас

Шапка, подвал, `.bmenu`, `.mbb` и `.modal` берутся из `index.html`. `sync_layout.py` копирует их на `objects.html`, `objects/*.html`, `services/*.html`, преобразует ссылки в `../…` и якоря в ссылки на главную. Также нормализует окончания строк/хвостовые пробелы и удаляет старый встроенный обработчик `openServiceModal` на вложенных страницах. Поэтому даже синхронизация требует проверки diff.

Внутренние страницы используют `.detail-hero`, `.detail-section`, `.detail-grid` и `.catalog-cta`. У услуг в первом блоке фотография; у отраслей и объектов — информационная панель `.object-focus`. Не заменять её фотографией только потому, что это умеет общий генератор.

## Формы и хранение

- `CONFIG`: бренд Dis Cleaning, телефон `+77076203813`, WhatsApp `77076203813`, регион Кордай / Алматы. `webhookUrl` пуст; локальная копия включена.
- `openServiceModal(subject)` сохраняет контекст услуги/объекта в `#orderService`. `submitOrder` проверяет телефон, готовит текст, кодирует его через `encodeURIComponent`, открывает WhatsApp. Пользователь отправляет сообщение самостоятельно; открытие окна не подтверждает доставку.
- `sanitex_leads` — существующий ключ локальных заявок; префикс исторический, переименование потеряет доступ к накопленным данным. `stx-lang` — язык; `dis-cleaning-pest-total` — общий счёт игры. Публичные интерфейсы обрабатывают недоступность localStorage.
- `admin.html` сначала пробует `GET /api/leads`, затем локальное хранилище. Фильтры, статистика, статусы, удаление и CSV находятся внутри страницы. Изменение статусов/удаление здесь сохраняется локально, не является серверной синхронизацией.
- `server.js` запускается через `npm start` на 8080, обслуживает статику и простые `/api/order`, `/api/leads`; `server.py` — альтернативный сервер. Публичная форма сейчас не вызывает `/api/order`.
- Это не готовая защищённая CRM. Не включать новую серверную доставку, публикацию панели или webhook попутно с интерфейсной правкой. Данные клиентов не включать в эталоны, скриншоты или коммиты.

## Скрипты: что нельзя перепутать со сборкой

`npm start` не генерирует страницы. У сайта нет обязательной сборки перед запуском.

- `tools/build_catalog.py` — действующий, но массовый генератор: 72 внутренние публичные страницы плюс секция `#objects` на главной. Остальные секции главной сохраняет. Новые ручные изменения внутренних страниц может стереть.
- `tools/sync_layout.py` / `npm run sync-layout` — синхронизация общих блоков, не отдельных текстов или функций.
- `tools/refresh_homepage.py`, `style_home_features.py`, `build_index_html.py`, `build_all_service_pages.py`, `build_js.py`, `build_perfect_css.py`, `generate_dis_cleaning_theme.py`, `unify_styles_and_fix_all.py`, `update_*`, `inject_*`, `refine_*`, `install_*`, `process_*` и загрузчики изображений — миграции/исторические преобразования. Их повторный запуск не является штатным шагом. Даже идемпотентный декоратор может изменить принятую основу.
- Старые проверки `verify_*`, `audit_i18n.py` и прочие утилиты могут опираться на прежнюю структуру. Актуальные проверки публичного сайта: `audit_public.py` и `tests/`.

При добавлении функционала в генерируемые страницы сначала понять соответствие HTML и шаблона. Сохранить функцию и в источнике генерации, и в нужных HTML. Не запускать массовую генерацию, пока она может затереть другие наработки.

## Проверки

`python tools/audit_public.py` проверяет все публичные локальные ссылки, якоря, ресурсы, JSON-LD, номера контактов и отсутствие ранее удалённых блоков.

`npm test` запускает Playwright: все публичные страницы на 320, 390, 768, 1024, 1440, 1920 px; JavaScript и загрузку ресурсов; заявку с перехватом WhatsApp; слайдер, язык, меню, FAQ, фокус; два сценария игры. Панель администратора и серверная CRM этим набором полноценно не проверяются.

Тест `Visual review artifacts` сохраняет снимки в игнорируемую папку `artifacts/`, но не сравнивает пиксели с эталоном. Успешные тесты не дают права менять дизайн вне задачи.
