## Реализация

Next.js **16.3.7**, React / React DOM **19.3.0**, App Router. Версии закреплены в package-lock. Все 73 публичные страницы при миграции были представлены JSX-компонентами и предрендерились на сборке. По последующему заданию владельца 30.09.2026 текущие 70 публичных страниц используют адреса без `.html`: `/`, `/objects`, `/services/klopy`, `/objects/dentistry`, `/instructions`. Старые известные адреса перенаправляются кодом 308, включая `/index.html` → `/` и `/admin.html` → `/admin`. Ссылки, canonical, Open Graph, JSON-LD и sitemap обновлены. Реестр содержимого сохраняет исходные ключи `.html`; преобразование — `lib/public-routes.cjs`. Неизвестные страницы возвращают 404. Для применения на домене нужно опубликовать новую Next.js-сборку; настройки не действуют на прежнем статическом хостинге.

- `app/` — маршрутизация, metadata, layout, 404 и API.
- `content/pages/*.jsx`, `content/pages.js`, `content/routes.json` — содержимое и реестр страниц.
- `components/SiteHeader.jsx`, `SiteFooter.jsx` — общий каркас с прежним порядком элементов для главной и внутренних страниц.
- `lib/site-config.js`, `lib/site-interactions.js`, `components/SiteInteractions.jsx` — принятые словари, RU/KZ, меню, слайдер, модальные окна, телефон, WhatsApp, локальная копия заявки. Инициализация и освобождение обработчиков/таймеров выполняются через React lifecycle. Inline JavaScript заменён декларативными `data-action`.
- `content/seo.json` — сохранённые метаданные, canonical, Open Graph, JSON-LD. Analytics с прежним ID подключается через `next/script` на главной, как в исходной версии.
- `components/AdminPanel.jsx`, `css/admin.css` — прежняя панель с React-состоянием, поиском, фильтрами, статусами, CSV и удалением.
- `app/api/order/route.js`, `app/api/leads/route.js`, `lib/leads.js` — прежние локальные API-контракты в Next Route Handlers.
- `tools/prepare-next.cjs` — подготовка CSS, изображений, иконок, robots и sitemap в `public/`. HTML, Git, backup, исходный код и заявки туда не копируются.
- `tools/run-next.cjs` — запуск с прежним портом 8080 по умолчанию и поддержкой `PORT`.

Исходные 161 файл HTML/CSS/JS/изображений проверены по манифесту backup и сохранены побайтно. Они остаются доступной с диска статической версией, а не runtime-источником Next. Для нового сайта редактировать JSX и `lib/`. Старые генераторы не вызываются при dev/build. Порядок CSS, относительные ссылки, цены, тексты, поля форм и ключи localStorage сохранены. Удалённая ранее игра не возвращалась.

## Запуск

Требуется Node.js >= 20.9.

```sh
npm ci
npm run dev
```

Открыть `http://localhost:8080/`. Production:

```sh
npm run build
npm start
```

Другой порт в PowerShell:

```powershell
$env:PORT = '8084'
npm start
```

Для сохранённой статической версии: `npm run legacy:serve`. В разработке разрешён loopback `127.0.0.1`; автогенерация AGENTS.md отключена, чтобы Next не дописывал правила владельца.

## Границы результата

Перенос выполнен локально; на хостинг сайт не опубликован. Для Next runtime нужен Node-хостинг. API использует локальный файл `leads.json` (или `LEADS_FILE`) и постоянный доступный для записи диск; это прежняя локальная модель, не распределённая база и не защищённая CRM. Статусы и удаления панели, как раньше, сохраняются только в localStorage, а серверные данные читаются отдельно. Публичная форма по-прежнему открывает WhatsApp; отправку сообщения подтверждает сам посетитель.

RU/KZ сохраняет прежний охват: основной интерфейс и слайдер переводятся, подробные описания остаются русскими. Полный перевод и новая игра не входят в перенос.
