# SEO и география Dis Cleaning

После переноса на Next.js (30.09.2026) действующие метаданные и JSON-LD находятся в `content/seo.json` и выводятся через `generateMetadata` / React-компонент страницы. При изменении контента синхронно править этот файл; домен, canonical, Open Graph, JSON-LD, `robots.txt` и `sitemap.xml` должны согласовываться. `robots.txt` и `sitemap.xml` копируются в `public/` при сборке. Команды `tools/seo.py` ниже относятся к сохранённой статической версии и **не обновляют Next.js**. Проверка действующего сайта: `python tools/audit_next.py URL` и `npm test`.

География действующего сайта — только Алматы. По заданию владельца 30.09.2026 действующие URL очищены от `.html`, главная доступна по `/`. Старые известные адреса перенаправляются кодом 308. Canonical, Open Graph, JSON-LD и sitemap используют новые адреса; исходные ключи `content/seo.json` сохраняют `.html`. Цены, дизайн и текущие сценарии сохраняются. Исторические материалы `docs/baseline/` не обновляются.

## Настройка домена

Основной домен подтверждён владельцем по панели HOSTER.KZ: `discleaning.kz`. В `seo.config.json` указан `https://discleaning.kz`; SEO-разметка 73 публичных страниц, `robots.txt` и `sitemap.xml` обновлены для этого адреса. Перед завершением публикации нужно включить HTTPS и проверить домен на хостинге.

При смене домена после подтверждения владельцем указать HTTPS-адрес без пути в `site_url`. Не применять примерный домен к рабочим страницам. Альтернатива — переменная окружения `SITE_URL`, имеющая приоритет над файлом. Проверить её значение перед применением.

Необязательные поля `google_site_verification` и `yandex_verification` принимают реальные коды из поисковых консолей. Переменные `GOOGLE_SITE_VERIFICATION` и `YANDEX_VERIFICATION` имеют приоритет; пустое значение удаляет соответствующий ранее установленный метатег. Это публичные коды, не пароли и не токены доступа.

```sh
python tools/seo.py
python tools/seo.py --diff
python tools/seo.py --apply
python tools/seo.py
```

Первые две команды ничего не записывают. `--apply` применяет рассчитанные изменения. Без домена все режимы только выводят отчёт. Повторный запуск после применения должен показать 0 изменённых файлов. Изменяется только SEO-разметка head; тело страницы, цены, ресурсы и относительные ссылки сохраняются.

Инструмент обрабатывает главную, каталог и существующие страницы `services/` и `objects/`. Он создаёт абсолютные canonical, Open Graph и Twitter Cards, связанные LocalBusiness / WebPage / Service / BreadcrumbList и sitemap. Минимальная цена берётся из видимого блока стоимости услуги и записывается как `PriceSpecification.minPrice`, без выдуманного максимума. Физический адрес, лицензии, рейтинги и расписание не добавляются без подтверждённых данных.

Действующий `build_catalog.py` использует ту же функцию обработки head. Его массовый запуск для SEO не нужен. Исторические миграционные скрипты не являются актуальными источниками сайта и не должны запускаться; их прежнее содержимое не переопределяет новые требования.

На главной `LocalBusiness.hasOfferCatalog` содержит 21 услугу из видимых карточек `#services`, с существующими URL и идентификаторами Service. Для 19 карточек с ценой используется `PriceSpecification.minPrice` в KZT; для клининга и дезинфекции цена не выдумывается. Каталог не дублируется на внутренних страницах, где нет такого видимого списка.

`FAQPage` на главной содержит только 8 опубликованных вопросов и ответов из `#faq`, на русском языке. На страницах без FAQ этот тип не добавляется. Разметка не вводит новых гарантий, сроков проветривания или заявлений о безопасности и не обещает расширенный FAQ-результат Google. После изменения видимого каталога или FAQ повторно применить SEO-инструмент; браузерный тест сверяет разметку с фактическими русскими текстами после переключения языка.

## Индексация и проверка

`robots.txt` доступен без домена, строка Sitemap появится после настройки. `/admin` исключён из sitemap и содержит noindex; `/admin.html` перенаправляет на него. Обход страницы разрешён, чтобы робот мог прочитать запрет индексации. robots.txt и noindex не заменяют контроль доступа к панели и API.

```sh
python -m unittest discover -s tests -p "test_seo.py"
python tools/check_baseline.py
python tools/audit_public.py
npm test
```

После публикации проверить ответы 200 и Content-Type у robots.txt и sitemap.xml, доступность всех canonical, отображение метатегов в исходном HTML. Затем подтвердить право владения доменом в Google Search Console и Яндекс Вебмастере и отправить sitemap. DNS, хостинг и внешние кабинеты этим инструментом не изменяются.
